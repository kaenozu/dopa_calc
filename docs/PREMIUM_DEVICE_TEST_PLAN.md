# PREMIUM 演出 実機テスト計画

CI の widget/unit test で overflow・構造・Cue別SEマッピング・専用PCM WAV構造・ハプティクス順序・SKIPキャンセルは確認済み。本計画は**GPU描画負荷・フレーム安定性・実機音量/振動・PUSH/シャッターの体感**を対象とする。

## 検証デバイス

| デバイス | 画面サイズ | 用途 | 優先度 |
|----------|-----------|------|--------|
| 低-end Android（Snapdragon 6系以下） | 720×1280 | パフォーマンス境界線 | ★★★ |
| 中端 Android（Snapdragon 7系） | 1080×2400 | 主力テスト | ★★★ |
| 小型 Android（5.0インチ以下） | 360×640 | overflow確認 | ★★★ |
| 高端 Android（Snapdragon 8系） | 1440×3200 | 基準値 | ★★ |

## Debug演出診断パネル

`flutter run` のdebug buildでは画面右上に `DEBUG FX` パネルを表示する。`kDebugMode` でガードしているためrelease UIには表示しない。

- `FORCE PREMIUM`: 入力式を作らず `777` の強制PREMIUMを開始する。
- `CUE`: 現在のEffectCueを表示する。
- ログ: 演出開始からの相対時刻（ms）で `CUE` / `SE` / `HAPTIC` / `CTRL` を記録する。
- `CLEAR`: ログと相対時計をリセットする。演出自体は停止しない。
- パネル開閉ボタン: ログを隠して画面占有を減らす。

実機では `CUE` の発火時刻に対して `SE` と `HAPTIC` が何ms後に出ているかを確認し、PUSH・シャッター・復活・JACKPOTの体感ズレを数値で記録する。

## フレーム時間目標

| 指標 | 目標 | 許容 | ブロッカー |
|------|------|------|-----------|
| 平均フレーム時間 | ≤11.1ms (90fps) | ≤16.6ms (60fps) | ＞22ms |
| 1%ile フレーム時間 | ≤16.6ms | ≤22ms | ＞33ms |
| ジャンクフレーム率 | ＜1% | ＜3% | ＞5% |
| メモリ使用量増分 | ≤30MB | ≤50MB | ＞80MB |

## テスト項目

| # | テスト項目 | 合格条件 |
|---|-----------|---------|
| T-01 | `7×1111` でPREMIUM発動 | NORMAL→CHANCE→激熱→PUSH→シャッター→暗転→復活→PREMIUMの8ビートと結果解放が全て表示される |
| T-02 | PREMIUM総尺 | 8ビート化後も演出本体が約9秒で完了し、冗長に感じない |
| T-03 | PUSHカウントダウン | `3→2→1` が視認でき、PUSH表示と見出しが競合・overflowしない |
| T-04 | シャッター役物 | 左右から閉じて再度開き、直後の完全暗転との切り替えが破綻しない |
| T-05 | 復活白フラッシュ | 暗転後に白フラッシュ→リング→復活役物の順で認識でき、過度な残像や長時間白画面がない |
| T-06 | SKIPボタン | PUSH・シャッター・暗転・復活・結果解放の各フェーズから即時結果へ遷移できる |
| T-07 | フレームレート（中端） | PUSH/シャッター/JACKPOTを含むDevTools平均≤16.6ms |
| T-08 | フレームレート（低-end） | DevTools平均≤22ms、ジャンク＜5% |
| T-09 | メモリリーク（10回連続発動→SKIP） | メモリ収束（50MB以内） |
| T-10 | Reduce Motion ON | カウントダウン進行・シャッター移動・常時アニメーション・強いフラッシュを停止し、静的装飾とSKIPは利用可能 |
| T-11 | 先バレ専用SE | 短い上昇チャープが先バレとして明確に認識でき、1.16x再生でも耳障りな高域にならない |
| T-12 | 図柄ロック/PUSH | 図柄ロックは0.90xの重い`impact.wav`、PUSHは1.06xの鋭い`impact.wav`として聴感差があり、振動と同期する |
| T-13 | シャッター専用SE | 低音衝撃＋金属リング＋ノイズが0.72xで再生され、役物閉鎖に十分な重量感がある。低-end端末でも音割れ・長い再生遅延がない |
| T-14 | 完全暗転 | 暗転入りで再生中SEが止まり、暗転中は無音・無振動を維持する |
| T-15 | 復活専用SE | 低音衝撃＋上昇スイープが0.88xで白フラッシュ/役物落下に同期し、暗転からの復活感を作る |
| T-16 | JACKPOT専用SE | 4音アルペジオ＋高域スパークルが1.08xでPREMIUM最終到達感を作り、復活音と明確に区別できる |
| T-17 | PUSHハプティクス | 中→中→強の3段振動が約0.48秒で同期し、カウントダウンのテンポと不自然にズレない |
| T-18 | シャッターハプティクス | 強→長振動が役物閉鎖の重さとして感じられ、過剰な長振動にならない |
| T-19 | 復活/JACKPOTハプティクス | 復活は長→強、JACKPOTは長→強→長として聴覚演出と同期し、端末ごとに不快な長さにならない |
| T-20 | SKIP/RESETキャンセル | PUSH/JACKPOT等の途中でSKIP/RESETしても、その後に予約済み振動が1回も発火せずSEも停止する |
| T-21 | 音量バランス | 既存assetと専用合成SEの間で突然のクリップ・著しい音量差がなく、端末音量50%で耳障りにならない |
| T-22 | 初回発動フレームスパイク | SoundManager初期化時の専用SEプリウォーム後、初回PREMIUMでも先バレ/シャッター/復活/JACKPOT開始時に専用SE生成由来の目立つジャンクがない |
| T-23 | BytesSource再生互換性 | 各検証Androidで4種の専用PCM WAVが全て再生され、無音・途中切れ・再生開始失敗がない |
| T-24 | 結果クライマックス | 長い指数表記でも画面内に収まり、1.5秒表示またはSKIPで終了する |
| T-25 | ランク差 | CHANCEにはPUSHが出ず、激熱はPUSHまで、PREMIUMだけシャッター/JACKPOTへ到達する |
| T-26 | 高強度描画 | 盤面ランプ・流星・稲妻・PUSH・シャッターを重ねてもフレーム時間目標を満たす |
| T-27 | Debug診断時刻 | `FORCE PREMIUM` で8ビートを再現でき、各Cueに対するSE/Hapticの相対時刻をログで読み取れる |

## 測定方法

```bash
flutter run --profile -d <device_id>
# DevTools → Performance → 録画開始 → 7×1111= → 演出完了まで待機 → 停止
```

フレーム計測はprofile buildを使う。Cue/SE/Hapticのタイミング確認だけは診断パネルが必要なためdebug buildで実施する。

```bash
flutter run -d <device_id>
# DEBUG FX → FORCE PREMIUM → ログの相対msを確認
```

PUSH・シャッターは個別にフレームスパイクを確認し、平均値だけでなく1%ileとジャンク率も記録する。

音・振動確認では端末音量50%を基準にし、同じ入力を3回連続で再生してタイミングのばらつきも確認する。PUSH/JACKPOT中のSKIPは各端末で最低5回繰り返し、遅延ハプティクスが終了後に漏れないことを確認する。

専用合成SEは先バレ→シャッター→復活→JACKPOTの順で個別に聴き、特にシャッターの低域とJACKPOTの高域が端末スピーカーで潰れないかを確認する。低-end端末では初回PREMIUMと2回目以降を比較し、プリウォーム後も再生開始レイテンシに差がないことを確認する。
