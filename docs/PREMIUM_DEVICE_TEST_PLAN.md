# PREMIUM 演出 実機テスト計画

## 概要

`effect_overlay.dart` の PREMIUM ランク演出（`EffectRank.premium`）を実機で検証するためのテスト計画。
CI では widget test のみでoverflow・構造を確認済み。本ドキュメントは、**GPU描画負荷・フレーム安定性・実機での視覚品質**を対象とする。

## 1. 検証対象の演出構成

PREMIUM 演出は以下のレイヤーを重ねて描画する：

| レイヤー | Widget/ Painter | 最大描画数 |
|---------|-----------------|-----------|
| バックドロップ | `_EffectBackdrop` | 1（RadialGradient） |
| パーティクル+スパーク | `_CelebrationPainter` | 96 |
| 放射線 | `_CelebrationPainter` | 48 |
| リング | `_CelebrationPainter` | 4 |
| スキャンライン | `_CelebrationPainter` | 画面高さ/18 本 |
| 走査光 | `_SweepBeam` | 1 |
| エッジフレーム | `_EdgeFrame` | 1 |
| ランクバナー | `_RankBanner` | 1 |
| ヘッドラインカード | `_HeadlineCard` | 1（巨大フォント126px + ShaderMask + 二重描画） |
| 進行インジケータ | `_ProgressPips` | 最大4 |
| 衝撃フラッシュ | `ColoredBox` | 1 |
| 画面揺れ | `Transform.translate/rotate` | 全レイヤー |

### PREMIUM ビートシーケンス（確定時）

| ビート | headline | subline | 期間 | intensity |
|--------|----------|---------|------|-----------|
| 0 | ・・・・・・ | 何かがおかしい | 1000ms | low |
| 1 | 先 読 み 発 生 | 数字がざわついています | 1500ms | medium |
| 2 | 超・確・定 | 7系プレミアム | 1800ms | high |
| 3 | ドパ計算RUSH | 答えは最初から決まっている | 2500ms | extreme |

### PREMIUM ビートシーケンス（ランダム1%時）

| ビート | headline | subline | 期間 | intensity |
|--------|----------|---------|------|-----------|
| 0 | 違 和 感 | ただの計算では終わらない | 1200ms | medium |
| 1 | 1% 突 破 | 確定音は脳内で鳴らしてください | 1800ms | high |
| 2 | 超 計 算 | PREMIUM | 2600ms | extreme |

## 3. フレーム時間計画

### 目標値

| 指標 | 目標 | 許容範囲 | ブロッカー |
|------|------|---------|-----------|
| 平均フレーム時間 | ≤11.1ms (90fps) | ≤16.6ms (60fps) | ＞22ms |
| 1%ile フレーム時間 | ≤16.6ms | ≤22ms | ＞33ms |
| ジャンクフレーム率 | ＜1% | ＜3% | ＞5% |
| メモリ使用量増分 | ≤30MB | ≤50MB | ＞80MB |

### 各ビートの描画予算

| ビート | intensity | パーティクル | 放射線 | 推定描画負荷 |
|--------|-----------|------------|--------|------------|
| ビート0 | low | ~38 | ~12 | 低 |
| ビート1 | medium | ~56 | ~24 | 中 |
| ビート2 | high | ~74 | ~36 | 高 |
| ビート3 | extreme | ~96 | ~48 | 最大 |

### 測定方法

```bash
# Flutter DevTools の Performance タブで記録
flutter run --profile

# フレーム時間の自動計測（DevTools timeline）
# 対象: EffectOverlay 表示中の全フレーム
```

## 4. テスト項目一覧

### 4.1 基本動作

| # | テスト項目 | 確認方法 | 合格条件 |
|---|-----------|---------|---------|
| T-01 | PREMIUM発動確認 | `7×1111` を計算 | 4ビート全てが表示される |
| T-02 | ランダムPREMIUM | 任意の計算を100回以上繰り返す | 1回以上PREMIUMが発動する |
| T-03 | SKIP動作 | 演出中に「演出SKIP」ボタンを押す | 結果画面に即遷移する |
| T-04 | 全ランク遷移 | NORMAL→CHANCE→GEKIATSU→PREMIUMを順に確認 | 各ランクで色・ラベルが正しい |
| T-05 | ハプティクス | 各ビートで振動を確認 | 激度がlow→extremeで増加する |

### 4.2 パフォーマンス

| # | テスト項目 | 確認方法 | 合格条件 |
|---|-----------|---------|---------|
| T-06 | フレームレート（中端） | DevTools Performance で記録 | 平均≤16.6ms |
| T-07 | フレームレート（低-end） | 同上 | 平均≤22ms、ジャンク＜5% |
| T-08 | メモリリーク | 10回連続でPREMIUMを発動→ SKIP | メモリが収束する（50MB以内） |
| T-09 | 長時間再生 | ビート3の2500msをフル再生 | フレームドロップなし |
| T-10 | リビルド頻度 | DevTools Widget rebuild count | 1ビート中のrebuild≤5回 |

### 4.3 画面サイズ・overflow

| # | テスト項目 | 確認方法 | 合格条件 |

## 5. 測定手順

### 5.1 フレーム時間計測

```bash
# 1. プロファイルモードで起動
flutter run --profile -d <device_id>

# 2. Flutter DevTools を開く
#    → Performance タブ
#    → Recording 開始

# 3. PREMIUM を発動する
#    → 7 × 1111 = を入力

# 4. 演出が完了するまで待つ（約6.8秒）

# 5. 録画を停止し、フレーム时间を分析
#    → Frame Analysis で平均/最大/1%ile を記録
```

### 5.2 メモリ計測

```bash
# DevTools → Memory タブ
# → Recording 開始
# → PREMIUM を10回発動（SKIPで短縮）
# → 録画停止後、ヒープ使用量の推移を確認
```

### 5.3 スクリーンショット記録

各デバイスで以下を記録：
1. ビート0（低負荷時）
2. ビート3 extreme（最大負荷時）
3. SKIP直後（結果画面遷移）

## 8. 既知の制約

- **CIではフレーム測定不可** — ヘッドレス環境のためGPU描画が行われない
- **音響レビューはバイナリ対象外** — WAV配置とコード参照のみ確認済み
- **iOS検証はXcode環境が必要** — 現環境ではAndroidのみ実施可能
